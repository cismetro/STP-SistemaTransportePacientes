Implementação de Melhorias Cadastrais – Sistema de Transporte de Pacientes
Contexto

O sistema necessita de melhorias nos formulários de cadastro e edição de pacientes e motoristas, visando aumentar a integridade dos dados armazenados, reduzir inconsistências cadastrais e facilitar futuras integrações com bases governamentais do SUS.

O CPF é recomendado como identificador principal dos cidadãos nos sistemas de saúde, podendo ser utilizado juntamente com o Cartão Nacional de Saúde (CNS).

1. Pacientes – Edição
URL

/transporte/pacientes/editar

Requisitos
1.1 Validação de CPF

Implementar validação completa do CPF:

Remover caracteres não numéricos automaticamente.
Validar quantidade de dígitos (11 posições).
Validar dígitos verificadores.
Bloquear CPFs inválidos.
Bloquear sequências conhecidas:
00000000000
11111111111
22222222222
etc.
Exibir mensagem amigável ao usuário em caso de erro.

Exemplo:

CPF inválido. Verifique os números informados.

Logradouro	Texto	Sim

Bairro	Texto	Sim
Ponto de Referência	Texto	Não
Regras
Permitir edição posterior.
Armazenar no banco de dados.
Exibir nos detalhes do paciente.
Preparar estrutura para futura integração com CEP.

PROMPT PROFISSIONAL – Análise para Implementação da Validação de Placas de Veículos
Objetivo

Realizar uma análise técnica completa para implementar a funcionalidade de validação inteligente da Placa do Veículo no módulo de Transporte do sistema e-SUS, sem gerar código nesta etapa.

A implementação deverá ser planejada para garantir boa experiência do usuário, modularidade, segurança, facilidade de manutenção e compatibilidade com futuras integrações governamentais.

Sistema

Páginas envolvidas:

https://esus.cosmopolis.sp.gov.br/transporte/veiculos/cadastrar
https://esus.cosmopolis.sp.gov.br/transporte/veiculos/editar

A funcionalidade deverá estar disponível tanto na tela de cadastro quanto na tela de edição de veículos.

Objetivos da funcionalidade

Implementar um mecanismo que permita:

validar a placa digitada pelo usuário;
impedir placas inválidas;
padronizar automaticamente a entrada;
consultar informações do veículo através de APIs oficiais quando disponível;
preencher automaticamente os campos do cadastro;
permitir funcionamento mesmo quando a API estiver indisponível.
Requisitos Funcionais

A análise deverá contemplar, no mínimo:

1. Validação da placa

Avaliar a melhor estratégia para validar:

quantidade de caracteres;
somente caracteres alfanuméricos;
conversão automática para letras maiúsculas;
remoção automática de espaços;
remoção de hífens;
prevenção de caracteres especiais.

Aceitar os dois padrões nacionais:

Modelo antigo
ABC1234
Modelo Mercosul
ABC1D23

Caso a placa seja inválida:

impedir consulta;
impedir gravação;
informar o motivo ao usuário.
2. Consulta automática

Após a placa possuir um formato válido, analisar a melhor experiência para:

consultar automaticamente;
consultar ao perder o foco (onBlur);
consultar através de botão;
evitar múltiplas consultas desnecessárias.

Comparar vantagens e desvantagens de cada abordagem.

Priorizar integrações governamentais.

A arquitetura deve facilitar a substituição futura de uma API por outra sem necessidade de alterar a lógica principal do sistema.
